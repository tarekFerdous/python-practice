1. Stack: a plain list

Push and pop at the end of a list: append and pop() are both O(1).1 The last thing in is the first thing out.

stack = []
stack.append("(")      # push
top = stack[-1]        # peek (crashes if empty!)
stack.pop()            # pop, returns the item
if not stack: ...      # empty check: an empty list is falsy

Use it when the newest open thing must be closed first: brackets, undo, nested tags, "previous greater element". For brackets, a dict maps each closer to its opener: {")": "(", "]": "[", "}": "{"}.

Two edge cases sink most bracket solutions: a closer when the stack is empty ("]"), and openers left over at the end ("((").

2. Queue: collections.deque

list.pop(0) shifts every other item: O(n). A deque adds and removes at both ends in O(1).2

from collections import deque
q = deque()
q.append(x)            # in at the right
oldest = q.popleft()   # out at the left, O(1)
q[0]                   # peek at the oldest
deque(maxlen=3)        # keeps only the last 3; old ones fall off

Use it for first-in-first-out work: BFS (Lesson 7), a sliding window over time, the last N events. The request counter is Lesson 2's variable window again: append the new time on the right; while the oldest is too old, popleft().

Interview line: "I'll use a deque so dropping old requests from the front is O(1); a list's pop(0) would be O(n)."

3. Heap: heapq

heapq turns a plain list into a min-heap: heap[0] is always the smallest. Push and pop are O(log n); heapify on an existing list is O(n).3

import heapq
heap = []
heapq.heappush(heap, 5)      # O(log n)
smallest = heap[0]           # peek, O(1)
heapq.heappop(heap)          # remove smallest, O(log n)
heapq.heapify(nums)          # in place, O(n)
heapq.heappush(heap, -x)     # max-heap trick: store negatives

Top k: keep a heap of size k

Sorting everything for the k-th largest is O(n log n). Instead keep a min-heap of the k largest seen so far; when it grows past k, pop the smallest. At the end, heap[0] is the k-th largest. Cost: O(n log k) time, O(k) space, which beats sorting when k is small.

Tuples in a heap

Heaps compare items, and tuples compare element by element. So (value, list_index, position) is ordered by value first, and the extra fields tell you where the item came from. That's the whole trick for merging k sorted lists: start with each list's first item, pop the smallest, push the next item from the same list.

Total cost for N items across k lists: each item is pushed and popped once at O(log k) → O(N log k) time, O(k) heap space (plus the O(N) output).
