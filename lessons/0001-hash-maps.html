Hash maps · ~25 minutes

Replace the nested loop with a dict

The single most common move in coding interviews. Once you see it, a whole family of problems becomes O(n).

Your win today: solve Two Sum, Top K Words and Group Anagrams from a blank function, no AI, with tests passing. Two Sum is on the Tech Interview Handbook's list of essential hash-table questions; Group Anagrams is on its recommended list.1

1. Why a dict is fast

Asking x in my_list makes Python walk the list: O(n). Asking x in my_set or key in my_dict jumps straight to the answer: O(1) on average.2 So a loop that does a list lookup each time costs O(n²); swap in a dict and it costs O(n).

This is a space-time tradeoff: you spend extra memory (the dict) to save time.1 Say that phrase out loud in an interview; it shows you know why.

2. The pattern on Two Sum

Given nums and target, return the indices of the two numbers that add up to target.

Brute force: O(n²)

for i in range(len(nums)):
    for j in range(i + 1, len(nums)):
        if nums[i] + nums[j] == target:
            return (i, j)

With a dict: O(n) time, O(n) space

seen = {}                          # value -> index
for i, x in enumerate(nums):
    need = target - x
    if need in seen:               # O(1) lookup replaces the inner loop
        return (seen[need], i)
    seen[x] = i

Read it as one question asked at every step: "Have I already seen the number I need?" That question, and the dict that answers it, is the pattern.

Why check before storing x? So a number can't pair with itself: [3, 4], target 6, must not return (0, 0).

3. Three tools that build on the dict

from collections import Counter, defaultdict

Counter("banana")                  # Counter({'a': 3, 'n': 2, 'b': 1})
Counter(words).most_common(2)      # 2 most frequent (word, count) pairs

groups = defaultdict(list)
groups[key].append(word)           # missing key? an empty list is created first

sorted(words, key=lambda w: (-count[w], w))   # count high→low, then A→Z
  • Counter counts in one line. Ties in most_common come out in first-seen order,3 not alphabetically, so when a problem says "ties alphabetical", sort it yourself.
  • defaultdict(list) removes the "if key not in d: d[key] = []" dance. (Careful: .get() does not create the default.3)
  • A tuple as a sort key sorts by the first item, then breaks ties with the next.4 Negating a number makes that part descending.
